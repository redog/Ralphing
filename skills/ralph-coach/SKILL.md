# Ralph Coach Skill

Use this skill to advance the coaching program by one coherent, testable module.

## Required context

1. Read `README.md` for project boundaries and audience paths.
2. Read `coach/COACHING_PLAN.md` for current state and priorities.
3. Read existing material related to the selected module.
4. Read relevant templates and synthetic fixtures.

## Iteration

1. Select the highest-priority incomplete item that can become a teachable or
   testable increment in the current run.
2. Search the repository before assuming material is missing.
3. Define the learning outcome in observable terms: what should a participant
   be able to recognize, decide, or produce?
4. Create or improve the minimum complete set:
   - learner-facing explanation;
   - exercise with synthetic, company-neutral inputs;
   - facilitator instructions;
   - expected observations or answer criteria; and
   - a way to capture confusion and results.
5. Check that platform comparisons record exact model metadata and distinguish
   prompt effects from model, product, and tool effects.
6. Check that examples contain no employer, customer, employee, confidential,
   licensed, or identifying data.
7. Validate links, paths, examples, and instructions that can be tested locally.
8. Update `coach/COACHING_PLAN.md` with completed work, evidence still needed,
   new questions, and the next priority.

## Quality rules

- Teach workflows and evaluation, not collections of clever phrases.
- Preserve uncertainty and require evidence for consequential claims.
- Keep learner-facing material free of unnecessary agentic terminology.
- Keep unrestricted autonomous-loop material in the advanced technical track.
- Prefer one tested module over several untested outlines.
- Do not claim a participant outcome was validated until a rehearsal, model run,
  or human session produced evidence.
- Do not commit, push, publish, message, or upload without explicit authorization.
