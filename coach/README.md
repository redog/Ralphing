# Coach workspace

This directory is persistent state for developing Ralphing into a practical AI
coaching program. It is intentionally separate from learner-facing material.

The `ralph-coach` skill reads `COACHING_PLAN.md`, chooses one incomplete module,
builds or improves the learner material, exercise, facilitator notes, and
evaluation method, then updates the plan with evidence and unresolved questions.

Use [Coaching considerations: the human as a temporary harness](../docs/facilitator/coaching-considerations.md)
as the default facilitator lens. Coaching should make the surrounding controls
visible: objective, context, constraints, tools, iteration cadence, evaluation,
stop conditions, and persistence. The coach supplies those controls initially,
then deliberately transfers responsibility to the learner.

## Working rhythm

1. Select one incomplete coaching outcome.
2. Build the smallest teachable module.
3. Rehearse it with synthetic inputs.
4. Run it with a person or a five-platform comparison.
5. Record observations using `templates/coaching-retrospective.md`.
6. Revise the material and update the plan.

When teaching cause and effect, change one important variable at a time when
practical. Do not silently rescue a learner or teach successful prompt wording as
magic; explain which missing control the change supplied. Reduce scaffolding as
the learner demonstrates they can define the job, inspect evidence, refine,
verify, and decide when to stop.

Progress comes from observed learning, not the volume of generated pages.
