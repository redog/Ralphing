# Start here

AI becomes useful when it is treated as a participant in a controlled work
process, not as an answer vending machine. You do not need special vocabulary.
You need a real job, relevant evidence, a definition of success, and a way to
inspect the result.

## The first human-guided loop

Choose a small, reversible task such as summarizing notes, reorganizing a draft,
or extracting facts from a supplied document.

1. Describe the outcome you need and who will use it.
2. Supply the source material.
3. State important constraints and what the model must not infer.
4. Specify a useful output shape.
5. Ask the model to expose uncertainty or missing information.
6. Compare the output with the source.
7. Correct the request and repeat.
8. Save the request only when it reliably produces useful work.

Use the [prompt brief](../templates/prompt-brief.md) when a task matters enough
to repeat.

## A useful request has five parts

| Part | Question it answers |
| --- | --- |
| Goal | What real-world result do I need? |
| Evidence | What information may the model use? |
| Constraints | What must it preserve, avoid, or leave uncertain? |
| Output | What structure would make the result useful? |
| Verification | How will we tell whether it is correct? |

This is not a formula for magic wording. It is a compact specification. The
model may still make mistakes, and a different model may interpret the same
specification differently.
